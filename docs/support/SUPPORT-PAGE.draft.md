# Help with Trilorah

Tell us what you were trying to do and where it stopped working. A few specific details help us find the right next step.

## Start with the guides

- [Install Trilorah and rehearse your first service](../community/GETTING-STARTED.md).
- [Find a task guide](../community/README.md#guide-drafts).
- [Run or build the app from source](../community/BUILD-FROM-SOURCE.md).

If a guide's controls differ from your app, include that in your report along with your app version.

## Contact support

Email **support@trilorah.com** with:

1. Your Trilorah version, operating system and computer type.
2. What you expected to happen and what happened instead.
3. The steps that led to the problem and the exact error message, if any.
4. Whether it happens again with a short practice service.
5. A cropped screenshot if it makes the problem clearer.

For sound problems, name the selected input and speech engine. Say whether the audio level moves and whether new transcript words appear. For screen problems, say which display is affected and whether Trilorah's preview differs from the physical screen.

Use a short test example where possible. Do not include passwords, API keys, account tokens, payment details or private congregation information. If we need a diagnostic file or recording, we will explain what to provide; you do not need to send an entire sermon or service package with the first email.

## During a service

Keep presenting prepared content and use manual scripture lookup if recognition is unavailable. Stop listening or turn off Auto advance if those optional behaviours are getting in the way, then check the result on the actual output. If the problem prevents reliable presentation, use the fallback arrangement your team rehearsed.

Once the immediate task is under control, record the version, time and visible error so the problem can be investigated.

## Questions about your data

Email **privacy@trilorah.com** for questions or requests concerning personal data handled by Trilorah. Tell us which account or service is involved and what you need. Avoid including a password or an unnecessary copy of the data in the first message.

If a church manages the service or a separate self-managed installation, its operator may also need to help with material held there. We will use the details of the request to identify the appropriate route.

## Reporting a security concern

Send a private report to **support@trilorah.com** with the affected version and a safe description of the issue. Do not publish credentials or other people's information, and do not test against a church's live service or account without its authorisation.

We can then arrange an appropriate way to receive any sensitive diagnostic detail.
