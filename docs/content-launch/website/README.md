## Put the copy into the product

Read [AGENTS.md](../../../AGENTS.md), [product context](../../../.agents/product-marketing.md), [tone](../TONE.md) and [website briefs](../WEBSITE-WRITING.md) when implementing a page. Use the reader-facing sections of each draft; frontmatter, evidence and production notes stay internal. Convert repository links to real website routes and test the destination before rendering a link.

The FAQ draft is the shared answer source for the full FAQ, short homepage selection and download-page help. Avoid keeping three separately edited answers to the same question. The existing `/guide` uses [shared product-map lessons](../../../web/src/app/guide/lessons.ts); longer Markdown drafts need their own rendering path.

Keep page copy fitted to the design. A finished manuscript for every feature page is not a prerequisite: use the briefs and current implementation to write the text as that page is built. The new drafts do not approve a homepage slogan or replace the shared tone guide.
