# You already typed the programme once.

The service order arrives in a message. Welcome at ten, worship at five past, sermon at twenty-five past. Now someone needs to put the same plan into the presentation app.

Trilorah can start with those words. Paste the programme, or use **Scan** in the desktop app for an image, and review the proposed service segments before adding them to the run.

You still get the last word. Quite useful when “10:00” has been photographed at an angle.

## Keep the plan. Check the interpretation.

The review gives you rows to inspect and edit: names, types, ordering, and any times or durations found in the programme. Check an uncertain type, correct a misread time, or remove a heading that became a segment. Nothing joins the run until you add it.

For a simple rehearsal, start with four lines:

> 10:00 Welcome — 5 minutes  
> 10:05 Worship — 20 minutes  
> 10:25 Sermon — 30 minutes  
> 10:55 Closing — 5 minutes

Read the proposed rows against that source. If an image doesn't produce useful text, try a clearer photo or paste the words instead. Columns, decorative headings, and unusual formats still need a careful check.

## Give each segment its content

Once the order is in place, add the lyrics, scripture, slides, media, and operator notes needed for the service. “Worship” on a programme doesn't tell Trilorah which arrangement the team will sing. The programme gets the structure started; you supply and rehearse the material.

If you're adding a programme to an existing run, inspect the result carefully. The current workflow appends visible segments and replaces the separate service schedule with the imported plan. Importing twice can leave duplicate segments.

Start with an empty practice run, check the four-line example, and prepare one item under each segment. Then save the service. The [programme-to-service guide](../articles/16-turn-a-programme-into-a-service.md) takes you through the full preparation and review.
