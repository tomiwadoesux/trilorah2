## 1. Hovering between tabs should target the next tab

The user requested that moving over a gap between navigation tabs should reveal the next tab instead of closing every label.

The gap belongs to the next tab on its right. The behavior was checked across all three gaps. Following the later tooltip changes, this means the next tab's name appears above its icon; hovering does not expand its inline label.

## 2. Show the name above the icon on hover; expand on click

The user changed the interaction to separate identification from selection:

- Hovering an unselected icon shows its name centered above the icon.
- Clicking a tab selects its workspace view and opens the name inside the selected pill.
- The selected name stays visible inside the pill.
- Hovering another tab leaves the current selection intact.

The hover and click behavior was visually checked, and the build passed.

## 3. Make the hover name move smoothly left and right

The user requested polished movement as the pointer travels between neighboring icons.

The implementation now uses one shared name bubble that moves between icons and resizes to the current name. Text transitions follow the direction of travel. Reversing direction retargets the existing movement, and crossing a gap continues to the next tab without flickering.

Implementation details:

- Position transition: 220 ms with an easing curve that settles gently.
- Width transition: 180 ms.
- Name transition and bubble fade: 120 ms.
- Brief exit grace: 80 ms, preventing unnecessary disappearance during short crossings.
- Icon and label measurements update when layout, fonts, or control density change.
- Keyboard focus can reveal the name; Escape dismisses it.
- Reduced-motion preferences disable the motion effects.

Hovering keeps tab widths stable. Clicking still controls the selected pill and inline label. Pointer movement in both directions, gap handling, control densities, click selection, keyboard activation, and pointer exit were checked. The production build and Git whitespace check passed. Existing unrelated build warnings remained.

## 4. Continuing Codex on another device

The user asked whether their existing topics/chats would appear when continuing Codex elsewhere.

The guidance was that local Codex chat history is stored on this computer, so signing into another device alone should not be relied on to bring over these local chats and project files.

Remote access can show and continue chats on this PC using the same ChatGPT account and workspace. The host PC must remain awake, online, and have the desktop app running. Handoff can transfer an existing chat and its Git state to another connected computer with a matching saved repository project.
